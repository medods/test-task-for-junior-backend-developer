# Task Service

Сервис для управления задачами с HTTP API на Go.


## Основные изменения

В рамках тестового задания добавлена возможность создавать повторяющиеся задачи с различными типами периодичности.

### Новые поля в API

- `recurrence` — объект с конфигурацией повторения (опциональный).
  - `type` — тип повторения: `daily`, `monthly`, `specific_dates`, `even_odd`.
  - `every_n_days` — для `daily`: повторять каждые N дней.
  - `day_of_month` — для `monthly`: число месяца (1–31).
  - `dates` — для `specific_dates`: список конкретных дат.
  - `parity` — для `even_odd`: `"even"` (чётные дни) или `"odd"` (нечётные).
  - `start_date`, `end_date` — период действия повторения.

В модели задачи появились:
- `scheduled_date` — запланированная дата конкретного экземпляра задачи (заполняется при создании через `recurrence`).
- `recurrence_type` — тип повторения, если задача часть серии.
- `recurrence_group_id` — общий UUID для всех задач одной серии.

## Логика работы с повторениями

При создании задачи с `recurrence` сервис:
1. Генерирует список дат в заданном диапазоне согласно правилу.
2. Создаёт в базе транзакционно по одной задаче на каждую дату.
3. Присваивает всем созданным задачам один `recurrence_group_id`.
4. Возвращает в ответе **только первую** задачу (с минимальной датой из сгенерированных).

Это позволяет фронтенду при необходимости получить все задачи группы через метод `List` с параметром `group_id`.

## Изменения в эндпоинтах

### `POST /api/v1/tasks`
Принимает опциональное поле `recurrence`. Если оно передано, создаёт серию задач атомарно в одной транзакции.

### `GET /api/v1/tasks`
Добавлен query-параметр `group_id`. Если указан, возвращает все задачи с этим `recurrence_group_id`.

### `DELETE /api/v1/tasks/groups/{group_id}`
Удаляет все задачи, принадлежащие указанной группе повторения.

### `PUT /api/v1/tasks/{id}`
Теперь можно обновить `scheduled_date` у конкретного экземпляра задачи.

## Детали реализации

### Генерация дат
- Для `monthly` день месяца можно указывать от 1 до 31.
  - Если указано 31, а в месяце меньше дней, дата автоматически приводится к последнему дню месяца (28, 29, 30). Это даёт возможность ставить задачу на «последний день месяца».
- Все даты хранятся и обрабатываются с учётом времени (формат RFC3339), что оставляет возможность в будущем указывать конкретные часы и минуты.

### Валидация group_id
Используется библиотека `github.com/google/uuid` как для генерации идентификатора группы, так и для проверки UUID в path-параметрах.

### Тесты
Написаны unit-тесты для функций генерации дат и валидации входных параметров повторений.

## Что можно улучшить в будущем

- Метод `PUT /api/v1/tasks/groups/{group_id}` для изменения параметров повторения всей группы.
- Ограничение максимального периода `end_date` (например, полгода или год) для предотвращения слишком больших серий.
- На фронтенде тип `specific_dates` может использоваться как «единичная задача на выбранную дату» — подставить текущий день по умолчанию.
