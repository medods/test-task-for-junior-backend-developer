# Task Service
Сервис управления задачами с поддержкой автоматической генерации по шаблонам.

## Общее
При реализации новой функциональности приоритетом было сохранение существующей архитектуры проекта. 

## API Эндпоинты
### Задачи
`POST /api/v1/tasks` - создание новой задачи. Если в теле запроса указан объект recurrence, сервис автоматически создаст шаблон и сгенерирует серию задач.

`PUT /api/v1/tasks` - обновление информации о существующей задаче.

`GET /api/v1/tasks` - получение списка всех задач.

`GET /api/v1/tasks/{id}` - получение детальной информации о конкретной задаче.

`DELETE /api/v1/tasks/{id}` - удаление задачи.

### Шаблоны
Управление логикой автоматической генерации вынесено в отдельные эндпоинты:

`POST /api/v1/templates/{id}/enable` - активация шаблона. Возобновляет автоматическую генерацию задач планировщиком. Операция идемпотентна.

`POST /api/v1/templates/{id}/disable` - деактивация шаблона. Приостанавливает генерацию новых задач, при этом уже созданные задачи остаются в системе. Операция идемпотентна.

## Архитектура
В рамках обновления схемы БД (миграция `./migrations/0002_create_scheduler_up.sql`) были внесены следующие изменения:

* Таблица `templates`: Хранит правила рекуррентности и конфигурацию генерации.

* Обновление `tasks`: Сущность задачи дополнена полями task_date (дата исполнения) и template_id (ссылка на родительский шаблон).

## Система рекуррентности
При создании задачи с указанием периодичности система регистрирует `Шаблон`, на основе которого генерируется первичный набор задач. Поддерживаются следующие типы:

* `Dates`: Разовое создание пачки задач на конкретные даты. Шаблон в базе не создается, так как отсутствует логика повторения.

* `Daily`: Генерация с заданным интервалом.

* `Monthly`: Генерация в конкретное число месяца.

* `Parity`: Создание задач по четным или нечетным дням.

## Механизм генерации
* При создании нового шаблона задачи генерируются на 1 месяц вперед.

* Фоновый процесс периодически сканирует активные шаблоны и добирает пул задач до актуального горизонта (1 месяц).

* Шаблоны являются неизменяемыми. Для прекращения генерации предусмотрена деактивация.

## API и Идемпотентность
Методы управления статусом шаблона `(Activate / Deactivate)` являются идемпотентными:

Повторный вызов активации для уже активного шаблона (или деактивации для выключенного) не приводит к ошибке и возвращает успешный ответ.

Это упрощает интеграцию с клиентами, избавляя их от необходимости проверять текущее состояние объекта перед запросом.

## Технические оптимизации
* Защита от дубликатов реализована на уровне БД через составной уникальный индекс `UNIQUE(title, task_date)`.

* Для эффективной выборки шаблонов планировщиком используется частичный индекс по столбцу `is_active`.

## Обработка граничных случаев
Для ежемесячных задач реализована логика «последнего дня»:

Если указанное число (например, 31-е) отсутствует в текущем месяце, задача автоматически переносится на последний календарный день этого месяца.

Это обеспечивает корректную работу бизнес-логики для таких процессов, как ежемесячная отчетность или выплаты.

## Дополнительные граничные случаи

* **Идемпотентность планировщика**: При пересечении циклов проверки планировщик не создает дубликаты задач. Система автоматически игнорирует попытки создания уже существующих записей благодаря констрейнту уникальности на уровне БД.
* **Временные зоны**: Все операции сравнения и генерации дат производятся строго в формате **UTC**.
* **Активация устаревших шаблонов**: При повторной активации шаблона, который долгое время был неактивен, генерация начинается с текущего момента времени.
